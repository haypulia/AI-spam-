# Разметка и разбиение основного датасета

Этот документ относится к `data/datasets/ai_assisted_spam_dataset.zip` и
основной библиотеке `src/email_ai_detector/`. Датасет с парами `source/target`
из отдельной папки `email_ai_detector/` имеет другую схему.

## Схема emails.jsonl

UTF-8, одна запись JSON на письмо. Индексы символов относятся к исходному
полю `text`, до нормализации: `[start, end)`, начало включено, конец исключён.
Это индексы символов Python, а не байтов UTF-8. Интервалы не относятся к теме,
HTML или изображению; происхождение этих зон хранится в `ai_elements`.

| Поле | Значение |
| --- | --- |
| `id` | Уникальный идентификатор письма |
| `topic_id` | Семейство/кампания; его варианты удерживаются в одной выборке |
| `seed_id` | `id` исходного письма для вариаций, либо null |
| `label` | `human`, `mixed` или `ai`; сохраняет признак частичной генерации |
| `ai_binary` | 0 для human, 1 для mixed и ai: наличие участия ИИ |
| `ai_origin` | `human`, `ai_full`, `ai_variation`, `ai_edited`, `ai_multistage` |
| `model` | Заявленная модель-генератор, для human — null |
| `prompt_type` | Способ генерации: `create`, `expand`, `human_modification`, `mixed`, либо null |
| `prompt` | Сохранённый запрос генерации, если имеется |
| `lang` | В текущем архиве `ru` или `eng` |
| `data_type` | Тип письма, например invoice, corporate_notice, marketing_legit |
| `is_spam`, `spam_type` | Отдельные сведения о спаме, не метка AI-происхождения |
| `subject`, `text`, `html` | Тема, текст и HTML |
| `ai_elements` | Сгенерированные зоны: subject, opener, body, cta, closer, html_template, image; ai_cta — обозначение CTA в части исходных записей |
| `ai_char_intervals` | Список пар символьных границ сгенерированных фрагментов text |
| `has_image`, `image` | Наличие изображения и его метаданные |
| `eml_path`, `mime_headers` | Путь исходного письма относительно корня датасета и заголовки |
| `split` | train, validation или test |
| `group_id` | Добавляется новым разбиением: идентификатор связной группы |
| `signals`, `edit_distance`, `norm_edit_distance`, `cosine_to_seed` | Вспомогательные признаки и сведения генерации |

Наличие полей разметки не доказывает реальное происхождение данных. Схема
описывает сохранённую синтетическую разметку; обучение классификатора и
ручная проверка достоверности происхождения — отдельные задачи.

## Воспроизводимое разбиение

Проверить существующее разбиение, не меняя данные:

```powershell
python scripts/split_dataset.py
```

Код возврата 1 означает пересечение групп между выборками или неизвестные
значения split. Проверяются идентификаторы, бинарные метки и границы интервалов.

Создать отдельный подготовленный датасет:

```powershell
python scripts/split_dataset.py --output data/interim/ai_assisted_spam_grouped
```

Можно передать собственный `--input path/to/emails.jsonl` или ZIP,
`--threshold 0.85` и `--seed 42`. Выходной каталог должен быть пустым.
Исходный файл, модели и старые отчёты не перезаписываются. Создаются
`emails.jsonl` и `split_report.json`: параметры, SHA-256 входного файла,
удалённые id и их представители, размеры групп и итоговая проверка утечек.

Правила сравнения:

1. Для поиска сходства используется text, а при его отсутствии — HTML без
   тегов. Нормализация Unicode NFKC, регистра, пробелов и невидимых символов;
   URL, адреса почты и числа заменяются маркерами. Сам исходный text не меняется,
   поэтому символьные интервалы сохраняются.
2. Сходство — Jaccard множеств последовательностей из трёх слов, порог 0.85.
   Для текстов короче трёх слов сравнивается вся нормализованная строка.
3. Совпадающие topic_id, template_id или group_id, ссылки seed_id на исходное
   письмо, совпадающие нормализованные тексты и пары выше порога образуют
   связные группы. Связи транзитивны, в том числе через удаляемые записи.
4. Среди похожих записей с одинаковым label и набором ai_elements остаётся
   один представитель. Удаление требует прямого сходства с сохранённым
   представителем. Разные классы или зоны не объединяются в одну запись,
   но остаются в одной выборке. Разметка представителя сохраняется целиком.
5. Целевые доли — 70/15/15, с балансировкой human/mixed/ai. Выполняются
   32 детерминированные попытки распределения целых групп. При крупных группах
   точные доли и баланс классов не гарантируются. Если независимых групп
   меньше трёх, подготовка завершается ошибкой.
6. На результате повторяется проверка тех же связей и сходства между выборками.

Метод обнаруживает сходство по указанному правилу, а не все семантические
перефразирования. Для известных шаблонов нужно сохранять template_id или
topic_id при генерации: общий HTML-каркас сам по себе не считается шаблоном
письма. По мере появления новых данных порог следует проверять вручную,
не подбирая его по качеству модели на test.

Проверка исходного архива 9 октября 2026: 1371 запись, 904 связные группы,
593 похожие пары, 42 группы пересекают исходные выборки при пороге 0.85.
Точные исходные тексты, topic_id и seed_id отдельно не пересекали выборки;
пересечения обнаружены дополнительным сравнением нормализованных текстов.

Подготовленный вариант: удалено 219 похожих записей с совпадающими классом
и набором зон; осталось 1152 письма (train 787, validation 182, test 183).
Пересечений групп по описанным правилам нет. Краткий отчёт проверки хранится
в `reports/dataset/split_audit.json`; полный список удалённых записей —
в `data/interim/ai_assisted_spam_grouped/split_report.json` после подготовки.

Новый emails.jsonl читается существующими загрузчиками:
`--dataset data/interim/ai_assisted_spam_grouped` для обучения и оценки.
Файлы EML и изображения не копируются; их относительные пути относятся
к исходному распакованному архиву. Текущие текстовые модели обучаются по JSONL.

После перехода на новое разбиение требуется заново обучить модели на train,
подобрать пороги только на validation и один раз оценить итог на test.
Сохранённые метрики прежнего разбиения нельзя выдавать за метрики нового.
