# Email AI Detector

Определение писем, полностью или частично сгенерированных языковыми моделями, на основе multi-signal анализа.

![license](https://img.shields.io/badge/license-MIT-blue)
![python](https://img.shields.io/badge/python-3.9%2B-blue)

Система разбирает `.eml`-письма, извлекает текст, HTML-разметку и текстовый слой изображений, считает набор стилистических и структурных признаков и оценивает вероятность машинной генерации. Помимо общего индекса детектор указывает, какие зоны письма выглядят сгенерированными — тема, приветствие, основной текст, призыв к действию, подпись, разметка, изображение — и подсвечивает конкретные предложения, если переписана только часть письма. Кроме офлайн-скорера доступен режим анализа через внешнюю языковую модель и их объединение.

## Структура репозитория

```text
.
├── src/email_ai_detector/       Библиотека
│   ├── config.py                Настройки и пути, читаются из .env
│   ├── cli.py                   Точка входа: prepare-data, train, analyze, evaluate, score
│   ├── data/                    Разбор .eml и загрузка размеченного датасета
│   ├── features/                Текстовые, структурные и OCR-признаки, лексиконы
│   ├── scoring/                 Модели, движок взвешивания сигналов, скореры, объяснения
│   ├── pipeline/                Пакетный анализ каталога с письмами
│   └── evaluation/              Метрики, маскировки, калибровка порогов, отчёты
├── scripts/                     Тонкие CLI-обёртки над библиотекой
├── tools/dataset_generation/    Генерация и валидация обучающего датасета
├── models/                      Обученные модели и калибровка порогов
├── reports/metrics/             Зафиксированные значения метрик и графики
├── docker/                      Dockerfile и docker-compose
├── tests/                       Тесты
└── data/                        Данные: raw, interim, processed, datasets
```

Инструменты в `tools/dataset_generation` собирают и проверяют обучающий датасет; запускаются из корня репозитория командой `PYTHONPATH=tools python -m dataset_generation.main`, результаты складываются в `data/interim/generated_dataset`.

## Установка

```bash
pip install -r requirements.txt && pip install -e .
```

Для распознавания текста на изображениях нужен Tesseract с языковыми пакетами `rus` и `eng`. Без него анализ текста и разметки работает как обычно, OCR отключается автоматически. Настройки читаются из `.env`, за образец можно взять `.env.example`.

## Быстрый старт

Распаковать датасет, обучить модели и посчитать метрики:

```bash
python scripts/prepare_dataset.py && python scripts/train_model.py && python scripts/evaluate_metrics.py --split test
```

Проанализировать каталог с письмами:

```bash
python scripts/run_analysis.py --input data/raw/drweb --scorer heuristic
```

Оценить одно письмо:

```bash
email-ai-detector score data/raw/drweb/sample.eml
```

Анализ через внешнюю языковую модель включается флагом `--scorer llm` и требует ключа `DEEPCODE_API_KEY`; ответы модели кэшируются в `data/interim/llm_cache`, поэтому повторный запуск не тратит запросы.

## Docker

Оба образа собираются из одного `docker/Dockerfile`: стадия `runtime` анализирует письма, стадия `metrics` считает метрики. В образах есть Tesseract с русским и английским языками, запуск идёт от непривилегированного пользователя, а при первом старте контейнер сам распаковывает датасет из `data/datasets`.

```bash
docker compose -f docker/docker-compose.yml build
```

```bash
docker compose -f docker/docker-compose.yml run --rm metrics
```

```bash
docker compose -f docker/docker-compose.yml run --rm detector
```

Каталоги `data/raw`, `data/processed`, `models` и `reports` монтируются с хоста, так что результаты остаются на машине после остановки контейнера.

## Данные

Размеченный датасет `data/datasets/ai_assisted_spam_dataset.zip` содержит 1371 письмо на русском и английском языках с разбиением train / validation / test — 977, 188 и 206 писем. У каждого письма известны бинарная метка, способ генерации, модель-генератор, размеченные зоны генерации и символьные интервалы сгенерированных фрагментов.

Письма кейса раскладываются в `data/raw` командой `python scripts/ingest_case_archive.py /path/to/AI_generated_emails.zip`.

## Метрики

Значения зафиксированы в `reports/metrics/`: файл `metrics_heuristic.json` содержит все метрики вместе с точками ROC-кривой, рядом лежит её график. Расчёт воспроизводится командой `python scripts/evaluate_metrics.py --split test`, а флаг `--markdown` дополнительно печатает отчёт таблицами. Пороги решения, зоны объяснения и сегмента подбираются на выборке `validation` во время обучения и сохраняются в `models/calibration.json`, поэтому тестовая выборка в подборе не участвует.

| Метрика (выборка `test`, скорер `heuristic`) | Значение |
| --- | --- |
| AUC-ROC | **0.9559** (95% CI 0.9200 – 0.9834) |
| PR-AUC | 0.9876 |
| Precision / Recall / F1 на калиброванном пороге 0.50 | 0.9932 / 0.8896 / 0.9385 |
| Полнота объяснений, macro recall / precision | 0.9202 / 0.7799 |
| Средняя сохранность AUC-ROC под маскировкой | 0.9783, худший сценарий 0.8900 |
| AUC-ROC на частично сгенерированных письмах | 0.9096 |
| Локализация сгенерированных фрагментов, F1 / IoU | 0.7321 / 0.6228 |

Кроме AUC-ROC считаются прикладные метрики: полнота объяснений сравнивает названные детектором зоны с разметкой датасета; устойчивость к маскировке проверяется семью преобразованиями, которые прячут следы генерации, не меняя метку письма; работа с частично сгенерированными письмами оценивается отдельно, вместе с точностью локализации переписанных фрагментов. Методика описана в `docs/metrics.md`, значения на выборке `validation` — в `metrics_heuristic_validation.json`.

## Проверка на данных кейса

Архив кейса разбирается и прогоняется целиком, сводка сохраняется в `reports/case_samples_summary.json`:

```bash
python scripts/run_analysis.py --input data/raw/case_samples --patterns '*' --output data/processed/case_samples_analysis.json
```

```bash
python scripts/summarize_case_samples.py
```

На 1941 письме архива детектор отмечает как сгенерированные все 1850 писем из `samples_prompt` при среднем индексе 0.986, 23 из 29 писем греймейла при среднем 0.777 и 17 из 61 письма спама при среднем 0.317.
